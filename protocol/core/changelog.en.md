# Changelog

## v2.0 — Extensive Co-Thoughts Architecture

- Upgraded the v1.3 linear Deep Path to a state-based Cognitive Architecture.
- Introduced the Cognitive Router.
- Separated Width and Depth.
- Introduced the Depth Engine and Source Dialogue (provisional project term).
- Introduced the Source Context Supply Chain.
- Introduced Temporal and Interpretive Context.
- Separated Historical, Contemporary, and Modern Interpretation.
- Introduced Socratic Examination and the Aporia state.
- Introduced the Premise Ledger.
- Defined SARA Knowledge Gate / Thought Gate interfaces.
- Added Attribution, Temporal, and Provenance axes.
- Introduced the Project Adapter Interface.
- Added Attribution / Temporal / Source Fidelity violations.
- Preserved v1.3 as the historical baseline.

### v2.0+ — SARA Verification Output Policy v1.0

- Defined SARA verification as a Verification → Revision → Re-verification loop rather than a post-hoc evaluation.
- Introduced the principle of always-on verification with progressive disclosure.
- Limited default output to core verification state, with detailed audit available on request.
- Required summary-level warnings for critical findings even when not requested.
- Clarified boundaries among Claim, Evidence, Verification, Uncertainty, and Human Judgment.
- Introduced Evidence Coverage, Verification Coverage, and Inference Ratio.
- Restricted non-rigorous meta-metrics such as unsupported Accuracy / Recall / Confidence values.
- Separated Replication Stability from Model Agreement.
- Replaced raw internal chain-of-thought with an auditable Claim → Evidence → Verification → Revision summary.
- Policy document: `protocol/sara_verification_output_policy_v1.0.md`
- Status: PROPOSED / PROJECT INTEGRATION

### Compatibility

Human Agency, Anti-Sycophancy, Epistemic Separation, Revision over Consistency, Information Gain, Non-Monotonic Revision, Checkpoint, and State–Evidence Separation from v1.3 remain in v2.0.

### Migration Rule

Do not overwrite the v1.3 document. Use v2.0 as the canonical active version.

## v2.0++ — Research Note One-Stop Adapter v0.1

- Added explicit triggers `/연구노트` and `/변환`.
- Accepted unambiguous natural-language Research Note requests as triggers.
- Defined the one-stop workflow: Research Note Engine → Existing-Note Consistency → Notion Mapping → Create/Update → Post-write Verification.
- Defined result states: NEW / REVISION / EXTENSION / NO_CHANGE / BLOCKED.
- Separated Notion persistence from epistemic verification.
- Prohibited bypassing locked/inaccessible targets and misreporting failed writes as saved.
- Canonical adapter protocol: `protocol/research_note_one_stop_pipeline_v0.1.md`.

## v2.0+++ — T51–T56 Research Note Disclosure / Full-Pipeline Integration

- Added T51 AI Authorship Disclosure / Provenance Transparency Test.
- Added T52 Real-Conversation Research Note Attribution Regression Test.
- Added T53 Cross-Document-Type AI Disclosure Regression Test.
- Added T54 AI Disclosure Rendering / Actual Research Note Output Test.
- Added T55 Multi-Note AI Disclosure / Provenance Consistency Test.

- Confirmed compatibility with D1–D9, NEW / REVISION / EXTENSION / NO_CHANGE / BLOCKED, Branch/Merge, D9, and human post-editing for the tested scope.
- Full-pipeline semantic integration is CLOSED FOR TESTED SCOPE.

The human remains the final epistemic decision authority.
