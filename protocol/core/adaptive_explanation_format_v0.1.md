# 적응형 설명 형식 프로토콜 v0.1

> 상태: ACTIVE GUIDANCE / DESIGN-LEVEL  
> 적용 대상: co-thoughts v2.0 및 이를 사용하는 프로젝트 어댑터  
> 목적: 설명의 정확성·이해 가능성·재현 가능성을 높이기 위해 작업에 적합한 표현 매체를 선택한다.

## 1. 목적과 범위

이 프로토콜은 설명을 텍스트에만 한정하지 않는다. 과제의 성격에 따라 구조화된 텍스트, 도식, 이미지, 인터랙티브 웹페이지, 애니메이션, 설명 영상 및 시뮬레이션을 선택하거나 조합한다.

이는 모든 응답을 시각 자료나 영상으로 만들라는 규칙이 아니다. 매체 선택은 사용자의 목적, 개념의 복잡성, 시간적 변화, 데이터의 성격, 정확성 요구, 제작 비용 및 접근성을 고려해 결정한다.

## 2. 기본 원칙

1. **목적 우선:** 매체의 새로움보다 사용자의 이해·판단·실행에 대한 기여를 우선한다.
2. **정확성 보존:** 시각적 단순화를 이유로 중요한 조건, 예외, 불확실성 또는 반례를 제거하지 않는다.
3. **근거 추적성:** 데이터·사실·인용에 기반한 시각 자료는 원자료, 기준 시점, 변환 및 해석을 추적할 수 있어야 한다.
4. **인식론적 구분:** FACT / INTERPRETATION / INFERENCE / HYPOTHESIS / SIMULATION을 시각적으로도 혼동하지 않게 표현한다.
5. **매체 적합성:** 정적인 관계에는 도식, 시간적 변화에는 애니메이션·영상, 탐색 가능한 변수에는 인터랙티브 표현을 우선 고려한다.
6. **인간의 판단권:** 시각화나 시뮬레이션은 판단을 지원할 뿐, 인간의 최종 판단과 책임을 대체하지 않는다.
7. **점진적 공개:** 핵심 설명을 먼저 제공하고, 상세 근거·절차·원자료는 필요에 따라 확장한다.
8. **실행 증거 분리:** 웹페이지·영상·시뮬레이션의 생성 사실을 실제 작동·통합·검증의 증거로 취급하지 않는다.

## 3. 설명 매체 선택 기준

| 과제 특성 | 우선 고려 매체 | 주요 목적 |
|---|---|---|
| 정의, 개념, 정밀한 조건 | 구조화 텍스트 | 정확한 의미 전달 |
| 구성 요소와 정적 관계 | 블록도, 구조도, 개념도 | 전체 구조 파악 |
| 순서와 의사결정 분기 | 플로차트, 시퀀스 다이어그램 | 절차와 분기 이해 |
| 인과관계와 경쟁 가설 | 인과도, 주장-근거 맵 | 관계와 논증 비교 |
| 공간·형태·외관 | 이미지, 지도, 주석 도해 | 시각적 맥락 파악 |
| 시간에 따른 변화·동작 | 애니메이션, 설명 영상 | 동적 과정 이해 |
| 사용자가 변수를 탐색해야 함 | 인터랙티브 웹페이지, 대시보드 | 조건별 결과 탐색 |
| 가정에 따른 결과 비교 | 명시적 시뮬레이션 | 조건부 결과 관찰 |

매체가 이해를 실질적으로 개선하지 않거나 신뢰할 만한 자료를 만들 수 없다면 텍스트를 유지한다.

## 4. 기술문서 작성 규칙

복잡한 기술·연구·운영 설명에는 항공 정비 매뉴얼 및 ASD-STE100의 명료성 원칙을 참고한다. 이는 ASD-STE100 공식 준수 또는 인증을 의미하지 않는다.

- 한 문장에 하나의 핵심 동작이나 판단을 담는다.
- 짧고 직접적인 문장과 일관된 용어를 사용한다.
- 전문용어는 처음 등장할 때 정의한다.
- 사실, 가정, 추론, 권고를 구분한다.
- 절차는 순서대로 제시하고 각 단계의 입력·작업·출력·판정 기준을 명시한다.
- 적용 조건, 예외, 실패 상태 및 복구 방법을 포함한다.
- 중요한 기술적 세부사항을 단순화를 이유로 생략하지 않는다.

가능한 경우 다음 구조를 사용한다.

1. 목적 및 적용 범위
2. 구성 요소와 용어
3. 작동 원리 및 데이터 흐름
4. 실행 절차
5. 판단 기준
6. 예외·실패 조건
7. 점검·검증 방법
8. 한계와 미확인 사항

## 5. 시각 자료·인터랙티브 자료·영상의 품질 규칙

### 5.1 도식과 이미지

- 노드, 화살표, 범례, 축, 단위 및 시간 범위를 명확히 표시한다.
- 연결선은 실제 관계를 나타내야 한다. 단순한 시각적 배치를 인과관계로 오인하게 하지 않는다.
- 개념도, 데이터 기반 차트, 예시 이미지를 구분한다.
- 실제 자료가 아닌 예시·합성 데이터는 눈에 띄게 표시한다.
- 복잡한 도식은 범례와 텍스트 설명을 함께 제공한다.

### 5.2 인터랙티브 웹페이지

- 각 조작 요소의 입력, 동작, 출력 및 초기 상태를 명확히 한다.
- 조작 결과가 어떤 가정과 데이터에 의존하는지 표시한다.
- 핵심 내용을 상호작용 없이도 이해할 수 있는 정적 요약으로 제공한다.
- 접근성, 키보드 사용, 작은 화면 및 오류 상태를 고려한다.
- 생성된 페이지의 코드·렌더링·실제 상호작용 검증 상태를 구분한다.

### 5.3 애니메이션과 설명 영상

- 영상의 학습 목표와 핵심 메시지를 먼저 정한다.
- 장면별 설명 순서와 내레이션을 구성한다.
- 시간·규모·인과관계의 시각적 표현이 실제 근거를 넘어서는 인상을 주지 않게 한다.
- 자막 또는 대본을 제공해 영상 없이도 핵심 정보를 확인할 수 있게 한다.
- 생성된 영상은 설명용 표현물이다. 실험·관찰·실제 시스템 작동의 증거로 취급하지 않는다.

### 5.4 시뮬레이션

- 입력 변수, 초기 조건, 가정, 모델 및 출력 지표를 명시한다.
- 시뮬레이션 결과를 관측 사실이나 예측의 확정값으로 표현하지 않는다.
- 민감도, 대안 조건 및 모델 한계를 가능한 범위에서 보여준다.
- 원 연구의 재현과 가상 조건의 시뮬레이션을 구분한다.

## 6. 출처와 데이터 보존

데이터 기반 표현에는 가능한 범위에서 다음을 기록한다.

- 원자료 및 출처 식별자
- 수집·조회 기준 시점
- 모집단·표본·공간·시간 범위
- 변환·집계·제외 규칙
- 지표 정의와 단위
- 시각적 인코딩 및 해석상 주의점
- 미확인·결측·추정 데이터 표시

도식·영상·웹페이지가 원자료와 다른 요약본을 제시한다면 그 차이를 밝힌다. 출처가 확인되지 않은 수치나 관계를 시각적 권위로 보강하지 않는다.

## 7. 기본 출력 조합

복합 과제에서는 다음 조합을 우선 고려한다.

- 기술 설명: 핵심 텍스트 + 구조도 + 단계별 절차
- 연구 검토: 주장·근거 맵 + 검증 상태표 + 상세 설명
- 시스템 분석: 아키텍처 도식 + 데이터 흐름 + 오류·복구 절차
- 동적 개념: 짧은 설명 + 애니메이션/영상 + 대본
- 데이터 분석: 차트 + 지표 정의 + 출처·방법 설명
- 조건 탐색: 정적 기준 설명 + 인터랙티브 도구 + 가정·한계

모든 매체를 한 번에 생성하지 않는다. 가장 높은 정보 이득을 제공하는 매체부터 선택한다.

## 8. 비적용 및 제한

- 단순 사실 확인, 짧은 번역, 단순 계산, 가벼운 대화에는 기본적으로 간결한 텍스트를 사용한다.
- 사용자가 텍스트 전용 또는 특정 매체를 요청하면 해당 요청을 우선한다.
- 적절한 도식·영상·인터랙티브 결과를 만들 수 없는 환경에서는 그 한계를 밝히고 지원 가능한 대안을 제공한다.
- 고위험 판단에서는 시각 자료만으로 결론을 제시하지 않는다. 근거, 불확실성 및 전문가 검토 필요성을 함께 표시한다.

## 9. 상태와 검증

이 문서는 설명 형식에 관한 설계 지침이다. 문서의 존재만으로 런타임 자동 매체 선택, 이미지·영상 생성, 웹페이지 실행 또는 설명 품질이 구현·검증되었다고 주장하지 않는다.

각 작업 보고에서는 다음을 구분한다.

- **Selected:** 선택한 표현 매체
- **Generated:** 생성된 산출물
- **Rendered:** 실제 렌더링 확인
- **Functionally tested:** 상호작용·동작 시험
- **Source verified:** 원자료·출처 확인
- **Unverified / Blocked:** 확인하지 못한 항목과 이유

## 10. 변경 원칙

이 지침은 co-thoughts v2.0의 인지 연산, SARA 검증 권한, 프로젝트별 출력 스키마를 대체하지 않는다. 실제 사용 사례와 테스트에서 확인된 문제를 근거로 개정한다.
