# Co-thoughts v2.0 Acceptance Tests

These are architecture-level acceptance criteria, not empirical performance benchmarks.

## T14 — Cognitive Router
Given the same topic, FAST/MIXED/DEEP must select different operation depth when cognitive demand changes.

## T15 — Width/Depth Separation
A breadth request must not automatically trigger source immersion; a source-immersion request must not be reduced to a list of related topics.

## T16 — Source Fidelity
Source-grounded output must not attribute model-generated material to the source without evidence.

## T17 — Temporal Attribution
Historical Author Mode must not silently use post-publication knowledge.

## T18 — Modern Interpretation Firewall
Modern interpretation must remain distinguishable from author-explicit claims.

## T19 — Socratic Aporia
APORIA is emitted only after a genuine premise/claim conflict is established; user hesitation alone is insufficient.

## T20 — Premise Ledger
A claim may have multiple premises with independent epistemic and verification states.

## T21 — SARA Knowledge Gate
External context cannot enter as trusted evidence merely because it is topically relevant.

## T22 — SARA Thought Gate
A dialogue-generated inference remains unverified until independently evaluated.

## T23 — Provenance
Every promoted claim/premise/evidence object retains origin and revision lineage.

## T24 — Non-monotonic Revision
New contradictory evidence can downgrade an existing verification state.

## T25 — Project Adapter
Domain-specific projects can consume Co-thoughts outputs without changing Co-thoughts core invariants.

## T26 — Fast-Path Protection
Simple tasks do not trigger unnecessary Deep/Depth/SARA workflows.

## Acceptance Principle

Passing these tests establishes architectural compliance only. It does not establish that Co-thoughts improves human learning, reasoning, or research outcomes; those require separate empirical evaluation.
