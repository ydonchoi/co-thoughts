# 설명 형식 라우팅 — 독립 평가 지침 v0.1

> 상태: PROTOCOL (데이터셋 미작성)
> 목적: 라우팅 규칙 작성자와 **독립적으로** 만든 설명 형식 선택 평가 세트를 구축한다.
> 평가자: 규칙 작성자가 아닌 평가자(예정: Codex). 일부 표본은 사람이 최종 판정한다.

## 1. 배경

기존 평가 세트(`tests/evaluation/format_routing_eval_*.json`)와 라벨은 모두 라우팅 규칙 작성자가 만들었으므로 점수가 낙관적이다. 이 지침은 다른 사람이 작성·라벨링하고, 라우터를 돌리기 전에 고정하는 세트를 정의한다.

## 2. 독립성 규칙 (평가자 준수 사항)

평가자는 과제와 라벨을 작성하는 동안 다음을 **열어보거나 참고하지 않는다.**

- `src/co_thoughts/explanation_format_router.py` 및 기타 라우팅 코드
- `tests/evaluation/` (기존 데이터셋, 평가기, 게이트)
- `tests/unit/test_explanation_format_router.py`
- `docs/testing/format_routing_keyword_eval_v0.1*.md`
- `docs/architecture/adaptive_explanation_router_integration_v0.1*.md`의 7·9·12·13절

과제는 **사람이** 요청을 어떻게 표현하는지 기술하는 것이지, 특정 구현을 시험하거나 피하는 것이 아니다. 라우터를 실행하지 않는다. 이 규칙은 지시할 수 있을 뿐 강제할 수 없으므로, 지시했다는 사실을 출처 기록 파일에 남긴다.

## 3. 라벨의 의미

각 과제는 어시스턴트에게 보내는 사용자 메시지 하나다. 라벨은 주의 깊은 사람이 읽었을 때 **사용자가 어시스턴트에게 만들어 달라고 요청하는 출력 형식 하나**다.

| 라벨 | 사용자가 요청하는 것 |
|---|---|
| TEXT | 글로 된 답만(설명, 요약, 목록, 표, 번역, 코드, 계산) 또는 시각·매체 출력을 요청하지 않음 |
| DIAGRAM | 구조 시각화: 흐름도, 구조도·관계도·개념도, 차트, 그래프, 타임라인, 마인드맵, 박스와 화살표 |
| IMAGE | 모양·외관을 보여 주는 그림·삽화·사진 |
| ANIMATION | 시간에 따른 변화를 보여 주는 움직이는 시각 자료(내레이션 불필요) |
| VIDEO | 영상·클립·녹화(보통 내레이션 또는 촬영) |
| INTERACTIVE | 사용자가 직접 조작하는 것(슬라이더, 컨트롤, 값을 바꿔 효과 보기) |
| SIMULATION | 가정에 따라 모델·시나리오를 돌려 결과를 계산 |

판정 규칙:

1. **주제가 아니라 요청된 출력.** 매체 단어가 주제로만 쓰이면("영상 코덱 원리 설명", "애니메이션의 역사", "그래프 이론이란") **TEXT**다.
2. **명시가 우선.** 사용자가 형식을 지정하면, 주제에 더 맞는 다른 형식이 있어도 그 형식으로 라벨링한다.
3. **라벨은 하나.** 여러 형식을 요청하면 결과물로 가장 분명히 원하는 **주 형식**을 고른다. 정말 동률이면 먼저 언급된 형식을 고르고 `ambiguous: true`로 표시한다.
4. **도구·방법을 묻는 질문은 TEXT.** "흐름도를 그려 주는 프로그램은?", "영상은 어떻게 만들어?"는 결과물이 아니라 정보를 요청한다.
5. **유용성으로 판정하지 않는다.** 시각 자료가 도움이 될 것 같다는 이유로 고르지 않고, 요청된 것을 라벨링한다.
6. **애매함은 허용하되 표시한다.** 주의 깊은 사람끼리 의견이 갈릴 수 있으면, 사례는 유지하고 가장 그럴듯한 라벨을 고른 뒤 `ambiguous: true`와 한 줄 `note`를 단다.

## 4. 구성

과제 80개: 영어 40개(`lang: "en"`), 한국어 40개(`lang: "ko"`). 언어별 구성:

| 그룹 | 언어별 개수 | 설명 |
|---|---|---|
| `explicit` | 7 | 일반적인 표현으로 형식을 요청("make a flowchart …", "흐름도로 보여줘") |
| `paraphrase` | 7 | 흔한 형식 명사 없이 형식을 요청("visualize …", "let me play with …", "사진", "직접 바꿔 보게") |
| `terse` | 5 | 아주 짧거나 동사가 없는 요청("Diagram of X, please", "구조도 부탁") |
| `plain` | 7 | 매체 어휘가 없는 일반 텍스트 과제 |
| `topic` | 8 | 매체 단어가 주제로만 쓰인 과제(도구·방법 질문 포함) |
| `mixed` | 6 | 여러 형식, 조건, 후속 요청("…그린 다음 설명해줘"), 요청과 설명이 섞인 과제 |

세트 전체에서 7개 라벨이 각각 최소 3번 이상 나오게 한다. 표현은 현실적이고 다양하게(존댓말·반말, 가끔의 오타 허용, 과학·비즈니스·소프트웨어·일상 등 다양한 분야) 하고, 거의 같은 문장은 피한다.

## 5. 산출 파일 (두 번째 평가자가 라벨을 보지 않고 작업할 수 있도록 두 파일로 분리)

`tests/evaluation/independent_v0.1/tasks.json`:

```json
{
  "version": "independent-0.1",
  "cases": [
    {"id": "I001", "lang": "en", "group": "explicit", "task": "…"}
  ]
}
```

`tests/evaluation/independent_v0.1/labels_annotator_a.json`:

```json
{
  "version": "independent-0.1",
  "annotator": "codex",
  "labels": [
    {"id": "I001", "expected": "DIAGRAM", "ambiguous": false, "note": ""}
  ]
}
```

`tests/evaluation/independent_v0.1/PROVENANCE.md`: 파일 작성 주체, 날짜, 알 수 있다면 모델, 2절의 파일을 열었는지 여부.

ID는 `I001`–`I080`으로 중복 없이 붙인다. `labels_annotator_a.json`의 모든 `id`는 `tasks.json`에 있어야 하고, 그 반대도 마찬가지다. 다른 파일은 수정하지 않는다.

## 6. 이후 절차 (평가자 담당 아님)

1. 라우터를 돌리기 전에 파일을 커밋해 고정한다.
2. 두 번째 평가자(규칙 작성자)가 `labels_annotator_a.json`을 **열지 않고** `tasks.json`만 보고 `labels_annotator_b.json`을 작성한다.
3. 일치도(Cohen's kappa)를 계산한다. 불일치 사례와 무작위 표본 20–30건은 사람(프로젝트 소유자)이 최종 판정해 `labels_adjudicated.json`에 기록한다.
4. 라우터를 평가자 A, 평가자 B, 사람 판정 표본 기준으로 각각 평가해 따로 보고한다. 결과는 사람 검증 벤치마크가 아니라 "사람 판정 표본을 포함한 교차 모델 평가"로 표시한다.
