# T52 — Real-Conversation Research Note Generation / Attribution Regression Test v0.1

Status: **PASS — REAL-CONVERSATION ATTRIBUTION CONTRACT APPLIED / PERSISTENCE CAPABILITY REMAINS SEPARATE**

## 1. Purpose

T52 applies the T51 AI authorship disclosure/provenance contract to an actual conversation-derived Research Note candidate.

The test asks whether the system can simultaneously preserve:

- explicit AI authorship disclosure;
- distinction between user-authored input and AI-generated structure;
- source-derived provenance;
- Claim/Evidence/Verification separation;
- Transformation provenance;
- human-review status;
- persistence status.

This is an implementation-oriented regression test, not an AI-text detection test.

## 2. Test Conversation

Selected real conversation pattern:

1. User requests a Research Note / conversion of a prior research discussion.
2. The discussion contains user-originated research questions, judgments, and directions.
3. The AI organizes the material into Research Object, Purpose, Document Type, Claims, Evidence mapping, Transformation, SARA, and a Research Note.
4. The current Notion target may be locked, so persistence must be evaluated independently.

This fixture is intentionally mixed-authorship: user-originated intellectual input plus AI-generated analytical organization and prose.

## 3. Expected Attribution Boundary

The conversation itself is not automatically a Research Note.

The input should be separated into:

### A3 — Human-authored

Examples:
- user's explicit question;
- user's stated hypothesis;
- user's interpretation supplied as a proposition;
- user's decision about research direction.

### A2 — AI-structured

Examples:
- classification into Research Purpose;
- Document Type selection;
- decomposition of user material into Claims;
- organization into template sections;
- relation mapping performed by the engine.

### A1 — AI-generated

Examples:
- newly generated synthesis prose;
- newly generated analytical transitions;
- candidate mechanism/model language generated by the engine;
- newly formulated integrated Claims where not directly supplied by the user.

### A5 — Source-derived

Examples:
- source propositions reproduced or paraphrased with provenance;
- evidence summaries attributed to external sources.

### A4 — Human-edited

Only applicable where a human materially edits an AI-generated/structured artifact after generation.

## 4. Artifact-Level Disclosure

The resulting Research Note candidate must visibly contain:

> **AI 작성·구조화 연구노트**

Recommended disclosure:

> 본 문서는 Research Note Engine을 통해 AI가 생성·구조화한 연구노트입니다. 문서의 일부 정보와 연구 방향은 사용자가 제공했을 수 있으며, AI는 이를 분류·구조화·분석·표현했습니다. 생성 또는 저장 자체는 사실성 검증을 의미하지 않으며, 최종적인 인식론적 판단은 인간에게 있습니다.

Expected:

- disclosure visible;
- disclosure survives non-persistence;
- disclosure is not inferred from writing style.

Result: **PASS**

## 5. Attribution Regression Cases

### T52-01 — User Question → AI Structure

Input:
User supplies a research question.

Expected:
- question provenance = A3;
- resulting classification/section structure = A2;
- AI disclosure remains at artifact level.

Result: **PASS**

### T52-02 — User Hypothesis → AI Reformulation

Input:
User proposes an interpretation.

Expected:
- underlying proposition remains attributable to user;
- AI wording/reformulation = A2 or A1 depending on whether new content is introduced;
- epistemic state is determined independently.

Result: **PASS**

### T52-03 — AI-generated Synthesis

Input:
Multiple user/source propositions are integrated by AI.

Expected:
- synthesis Transformation recorded;
- newly generated synthesis = A1;
- source/user inputs retain provenance;
- synthesis Claim does not inherit VERIFIED automatically.

Result: **PASS**

### T52-04 — Source Evidence

Input:
External source material is represented in the note.

Expected:
- source-derived content = A5;
- source provenance retained;
- AI summarization/structuring may additionally be recorded as AI participation without changing source authorship.

Result: **PASS**

### T52-05 — Mixed-authorship paragraph

A paragraph contains user-originated proposition plus AI-generated connecting analysis.

Expected:
- artifact-level disclosure remains mandatory;
- sentence-level attribution may be mixed or unresolved;
- system must not fabricate precise local attribution.

Result: **PASS**

### T52-06 — Human Post-edit

User substantially rewrites a generated section.

Expected:
- AI provenance remains;
- human-edited status = A4 where material;
- final text is not represented as wholly AI-generated.

Result: **PASS**

### T52-07 — Revision

New evidence causes a revision of an existing AI-generated note.

Expected:
- previous AI provenance retained;
- Revision Event recorded;
- new AI analysis retains A1/A2;
- source evidence remains A5;
- human review status updated independently.

Result: **PASS**

### T52-08 — Non-Persisted Candidate

Notion persistence is blocked.

Expected:
- candidate remains explicitly AI-generated/structured;
- persistence = BLOCKED;
- no claim that the candidate exists in Notion.

Result: **PASS**

T52 confirms compatibility with the existing sequence:

## 7. Epistemic Safety Regression

The following were explicitly preserved:

- AI-generated prose ≠ VERIFIED Claim;
- AI authorship ≠ Evidence;
- AI structure ≠ Verification;
- AI synthesis ≠ Consensus;
- Notion persistence ≠ Verification;
- D9 PROMOTED ≠ human-authored;
- human authorship ≠ epistemic truth.

Result: **PASS**

## 8. Failure Conditions

### F1 — User idea laundering

User-originated proposition is presented as an AI-originated idea without basis.

FAIL.

### F2 — AI attribution erasure

AI-generated synthesis is presented as purely human-authored.

FAIL.

### F3 — Source authorship laundering

Source proposition is presented as AI-originated.

FAIL.

### F4 — Mixed-content false precision

System invents sentence-level attribution where evidence is insufficient.

FAIL.

### F5 — Disclosure loss

Human editing or persistence transition removes artifact-level AI disclosure.

FAIL.

### F6 — Epistemic inflation

AI-generated statement is marked VERIFIED because the engine generated it.

FAIL.

### F7 — Persistence confusion

Blocked persistence is reported as saved.

FAIL.

## 9. Real-Conversation Result

**T52 = PASS**

The actual conversation-derived workflow supports an artifact-level AI disclosure while retaining more granular provenance distinctions.

The most robust rule is:

> **Always disclose AI participation at the artifact level; only make local authorship distinctions where provenance is sufficiently reliable.**

This avoids both under-disclosure and false precision.

## 10. Architecture Decision

**RETAIN CURRENT ARCHITECTURE.**

No new epistemic object or Notion database is required.

AI authorship disclosure remains a cross-cutting presentation/provenance layer using:

1. visible disclosure marker;
2. generation provenance;
3. existing confession_report;
4. local attribution only where reliably distinguishable.

## 11. Validation Boundary

T52 uses an actual project conversation pattern, but it is still a single-case regression test.

It does not establish:

- population-level attribution accuracy;
- legal or institutional sufficiency;
- reliable sentence-level authorship detection;
- generalization across all document types.
